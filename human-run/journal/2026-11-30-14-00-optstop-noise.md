# 2026-11-30 optstop: the "disagreement" was low-R noise, not a bug

Base CURRENT `1051-nofish-west-postfit` (refits were first run on 1044, then redone on 1051 after CURRENT moved).

## Why optstop's EHT disagreed with the paired eval
* `optstop --iters 0` (start table only) reproduces `ev` on the same plan and seed: 179.0 h (535 fin) vs 175.8 h (543 fin) at R 400k. Same function (`evaluate_blocks`); no censoring or lambda bug.
* The earlier refit used R 200k training / 400k eval. At WR+2m that is ~270 training finishes (0.14% finish rate) and ~540 eval finishes: the V fit is noise-dominated and the per-iteration eval (+-4% scatter, a different seed each iteration) cannot tell a bad table from a good one. The last iterate (277 h) was simply a bad noisy table.
* With R 2M training / 1.6M eval (2100-2500 finishes) on 1044 the iterates stay 178-185 h around the start table (175-182): the fit converges to the inherited table.
* Policy is hindsight-free: `attempt` resets on `st.clock > cut` (clock already elapsed) or the best-case floor only; V is regressed on elapsed time at the split from realised futures, which never enter the decision.

## Fix (optstop.rs)
All iterates (and the start table) are evaluated on one seed, paired; the best is returned (last element), so a noisy refit can no longer be worse than the start. A warning is printed when the training set has < ~1500 expected finishes.
