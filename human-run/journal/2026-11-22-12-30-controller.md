    frlg-human play-inspect --plan ... <file.state>      # map, party (decrypted), bag, money

- `play/session.rs`: the route is a list of stages (`play/legs.rs`); each surviving stage ends in a
  checkpoint (raw in-memory state for rollback, `states/human-play/<plan>-s<seed>/<frame>-<name>.state`,
  RAM sha1 in `checkpoints.jsonl`). A dead stage (blackout, soft-lock timeout, forced) rolls back:
  core restored, ilog and events truncated (earlier `rollback` events kept), human rekeyed, replayed.
  The human key is per stage (`stage * 1000 + retry`), so a run resumed at any checkpoint continues
  exactly as the uninterrupted one. Outputs are written at every checkpoint (ilog = prefix + new
  frames up to the last checkpoint). A dead branch leaves a picture and state under `<out>/dead/`.
- Checks (scratchpad `ctl-s2check.sh`): two runs with the same seed to `hideout-out` give the same
  ilog (sha1 d68870f3...); `--force-rollback hideout-out` gives a different one (fdbd9dc8...); both
  verify from boot (`play-verify`, RAM hashes at giovanni1 and hideout-out match).

## S3: primitives (done enough to play the legs below)

- `play/walk.rs`: a port of `bin/frlg-mapgraph`'s movement model (collision, warp tiles, ledges,
  connections, Cut trees, Surf start) as Dijkstra with small human tie-breakers (turns, grass, trainer
  sight lines). Live object positions from `gObjectEvents`, objects hidden by their flag left out,
  and the current map's collision read from the live grid `VMap` (gym beams). The plan is fixed
  before walking; encounters and trainers are handled when they happen (no emulator lookahead).
  Arrow and side-stair warps (`TryArrowWarp`, `field_control_avatar.c:825-940`).
- `play/prims.rs` `settle`: mash A (late by U{0..N}) until free; battles go to the battle bridge;
  nickname prompts confirmed; a reopened start menu closed with B.
- `play/menu.rs`, `play/items.rs`: multichoice/yes-no by `sMenu.cursorPos`, start menu by
  `sStartMenuOrder`, bag by pocket + live `ListMenu` cursor, TM case (HMs-first sort), party menu by
  `gPartyMenu.slotId`, field moves from the party menu, Fly by the region-map cursor, Bicycle
  registered to SELECT, options (battle style SET).
- Battles: `play/battle.rs` (the sim-policy bridge, merged) at one call site
  (`fallback_battle::battle`); the stand-in driver stays behind `--fallback-battle`.
- Not yet: marts, PC, Repel, Strength, Surf in practice (planner supports it, untested).
