## 2. Walker changes (`crates/frlg-human/src/play/walk.rs`, `ram.rs`)

- **Collision from live objects.** `Ram::objects` now reads `previousCoords`, facing, movement type, trainer
  type/range, map and elevation. Every active object blocks its current *and* previous tile, the two tiles
  `DoesObjectCollideWithObjectAt` checks (`decompiled/src/event_object_movement.c:4899-4915`); a lingering object of
  the previous map collides but is not matched to this map's templates. Off-screen objects of the current map sit at
  their RAM template (`TrySpawnObjectEvents` spawns from `gSaveBlock1Ptr->objectEventTemplates`, `:1808`;
  `SetObjEventTemplateCoords`, `overworld.c:448`), static `map.json` objects only when their flag is clear.
- **No step into an occupied tile.** Before each step starts, the next tile is checked against the live objects: an
  object only leaving it is waited out (<= 24 frames), one standing or stepping into it is planned around (counted as
  a "stop", not a bump). The game resolves the step on the frame it reads the held key, so this is exact.
- **Re-plan on new information without letting go.** When the set of live objects changes mid-step and the rest of the
  plan is spoiled (a node now blocked, seen, or watched), the walker plans again from the tile being entered and keeps
  holding the d-pad (`Follow::Refresh`). Refreshing on every flicker made it circle the Viridian Gym spinners; now only
  a spoiled plan refreshes, and a refresh never reverses straight back unless nothing else goes.
- **Trainer sight from RAM.** `CheckForTrainersWantingBattle` runs on every frame the player has control
  (`field_control_avatar.c:209`) and looks from the trainer's current coordinates along its current facing
  (`GetTrainerApproachDistance`, `trainer_see.c:122-143`), cut at the first collision (`CheckPathBetweenTrainerAndPlayer`,
  `:196-232`). On-screen trainers were skipped before (`walk.rs:419-421` in v4) and wanderers drawn from spawn
  (`:427-430`). Now: fixed-facing trainers' lines are walls (as before, cost of a fight); a *turning* trainer on screen
  (wanderer, `LOOK_AROUND`, `FACE_A_AND_B`) gets a **watch** set -- every line it can have from anywhere in its movement
  box (`WANDER_UP_AND_DOWN` only vertical) -- priced as a ~1.5 s wait; off screen, the watch set is a wall until it
  comes into view. Beaten flags now come from `data/scripts/trainers.inc` too (most trainer scripts live there, so in
  v4 no trainer ever counted as beaten and beaten trainers' lines stayed walls).
- **Spinners are passed walking.** A `LOOK_AROUND` / `FACE_A_AND_B` / `ROTATE_*` trainer turns to the player at
  once when the player *runs* inside its range box (`ObjectEventIsTrainerAndCloseToPlayer`: needs
  `PLAYER_AVATAR_FLAG_DASH` and the player within `trainerRange` on both axes, `event_object_movement.c:2772-2798`,
  used by `MovementType_LookAround_Step3/4` `:3044-3066` and every `FACE_*_AND_*` Step3); `player_step` clears the
  flag every frame it does not run (`field_player_avatar.c:135-145,178-184,516-523`). So steps into a spinner's
  box are walked (B released) and waits happen standing; wanderers never react (`MovementType_WanderAround_Step3`,
  `:2721`). This is what made R2b's walker (and the first R1 replays) fight Youngster Dan, Grunt 4 and the hideout
  grunts after a wait.
- **Walk-sequence trainers** (Lass Miriam, Mt. Moon 1F) walk the rim of their box with one facing per side
  (`MoveNextDirectionInSequence`, `:3909-3935`); `ObjInfo::poses` simulates the loop, so only the rim lines count
  (before: every facing from every box tile, which made her a "forced" fight).
- **Wait-for-facing.** Before entering a watched stretch the walker stops on the last safe tile and waits for a
  *visible* turn or step away, reacts (`U{15..30}`), and crosses. A wanderer keeps a facing for at least 32 frames
  (`gMovementDelaysMedium` {32, 64, 96, 128}, `MovementType_WanderUpAndDown_Step2`, `event_object_movement.c:3084-3093`),
  48+ when the turn is a step; a running crossing of one tile is ~8 frames after the reaction.
- **Plan skips.** A path through a sight line is logged once per trainer (`decision`: "no way around the sight line of
  X"); those are the plan's forced trainers. Avoidable ones are never crossed.
- **Warps and slides.** Same-map warps, loading warps (above); spin-tile slides followed to their end without a
  re-plan; connection crossings no longer stop the player (the map id switches one frame before the coordinates).
- **Accounting.** Every bump is a `warn` event with `"bump": true` and the stage; `walk::bump_summary` counts them per
  stage, and `frlg-human play` prints `bumps: N this session (stage n, ...); M in the whole log` at the end.
- **Detours** (`PROMPT.md`, *No detours*): at the first plan of every walk the planner also finds the shortest legal
  path (same walls, no grass/turn tie-breakers, no wait price, in tiles); a longer plan is a `warn` with the reason
  ("avoids N grass tiles", "avoids N tiles a turning trainer may see"), and a walk that ends longer than planned is a
  `warn` with its bumps / stops / battles / re-plans.
- `bin/frlg-mapgraph`: `blocked_tiles` skips objects whose flag is set; by default the flags `EventScript_ResetAllMapFlags`
  sets at new game (`decompiled/data/event_scripts.s:1013`, run from `new_game.c`), adjustable with `--flags-set` /
  `--flags-clear`. Pallet house door -> Oak trigger (12, 1): 13 tiles (15 with Oak's flag cleared; item 5).

**API for the early-stage agents:** unchanged signatures (`go`, `go_to`, `go_map`, `go_face`, `plan_len`, `plan_nodes`,
`Opts` gained `steps_only`, use `..Opts::default()`). New: `walk::live_objects`, `walk::bump_summary`, `Plan::tiles`,
`ObjInfo::{facings, offsets}`, `Ram::templates`, `LiveObject` has more fields (construct it only via `Ram::objects`).
A walk goal that is a door's arrival tile is never "stood on" (the game walks the player off it): use `go_map`.

## 3. The regression harness: `frlg-human play-walk`

`frlg-human play-walk --plan <plan> [human-run/walk-regress.json] [--case name] [--seed S] [--seeds n]` loads each case's
state, walks its legs and reports bumps, waits, detours and the trainers fought; a case fails on a bump, an error, or a
fight with a trainer in its `no_fight` list. `human-run/walk-regress.json` holds the 85 v4 bump sites (goal: where the
player stood 400 frames after the bump, or the warp's map), the Route 3 crossing and the Viridian Gym spinner loop.
